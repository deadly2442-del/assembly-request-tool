# 문항목록 만들기

자료요구서 PDF를 읽는 `split.py`를 작업 폴더 맨 위에 만들고, `data/문항목록.csv`의 현재 형식과 처리 규칙을 재현한다.

## 먼저 확인할 자료

1. 작업 폴더의 `AGENTS.md`, `PROGRESS.md`, `CONTEXT.md`를 읽는다.
2. `처리지침.md` 제2장을 읽고 접수·문항 분해 규칙을 확인한다.
3. `data/문항목록.csv`가 있으면 이를 현재 출력 계약이자 정답 예시로 읽는다. 기존 `split.py`가 있으면 구현 참고자료로 함께 읽는다.
4. `원문/*.pdf`의 실제 파일 수, 파일명, 첫 줄, 제출기한 줄, 문항 시작 줄, 세부항목과 비고 형식을 확인한다. 원문 PDF는 수정하지 않는다.

`99_완성본_잠금`은 열거나 풀지 않는다.

## 의존성

- PDF 처리는 `pypdf`만 사용한다. 표준 라이브러리는 사용할 수 있다.
- 작업 전에 `pypdf` 가져오기를 확인한다.
- 없으면 `pip install pypdf`를 사용자에게 보여 주고 허락을 받은 뒤에만 설치한다.

## 출력 계약

- 코드 파일은 작업 폴더 맨 위의 `split.py` 하나로 만든다.
- 결과는 `data/문항목록.csv`에 `utf-8-sig`로 쓴다.
- 열 순서는 `파일명 | 위원회 | 의원 | 제출기한 | 문항번호 | 요구내용 | 세부항목 | 비고`로 고정한다.
- 여러 세부항목은 한 셀에서 ` / `로 연결한다. 예: `가. 연도별 건수 / 나. 세부 내역(엑셀 파일로 제출)`.
- 비고는 앞의 `※`와 뒤따르는 공백을 제거한 본문만 저장한다. 예: `개인정보는 제외하고 제출할 것`.
- `수신:`, `담당 보좌관:`, `끝.` 줄은 문항 내용에 넣지 않는다. 담당자 이름·연락처는 어떤 출력이나 검증 보고에도 남기지 않는다.

## 추출 규칙

1. 첫 줄의 `○○위원회 ○○ 의원실 자료요구서`에서 위원회와 의원을 추출한다.
2. `수신:` 줄 안의 제출기한을 `YYYY-MM-DD`로 바꾼다.
3. 줄 맨 앞의 `숫자.`는 새 문항으로 시작한다.
4. `가.`, `나.` 등 한글 글머리는 앞 문항의 세부항목으로 넣는다.
5. `※` 줄은 앞 문항의 비고로 넣되, CSV에는 `※`를 저장하지 않는다.
6. 그 밖의 줄은 바로 앞에서 처리한 요구내용·세부항목·비고에 이어 붙인다.
7. 문항 내용과 문항 수를 코드에 직접 넣지 말고 실행할 때 PDF에서 읽는다.

## 교체된 문항목록을 기준으로 코드를 맞출 때

사용자가 `data/문항목록.csv`를 교체했다고 밝히면 그 파일을 정답 기준으로 취급한다.

1. 기준 CSV를 덮어쓰지 않은 상태에서 PDF를 메모리로 분석한다.
2. 열 순서, 행 순서, 모든 셀을 기준 CSV와 비교한다.
3. 차이를 필드별로 묶어 원인을 찾고 `split.py`의 일반 규칙을 고친다. 특정 문항의 값이나 파일 내용을 코드에 하드코딩하지 않는다.
4. 예상 결과가 기준 CSV와 완전히 같아진 뒤에만 완료로 판단한다.
5. 사용자가 재생성을 요청하지 않았다면 교체된 기준 CSV는 그대로 보존한다.

## 검증

- 파일명에 `_숫자문항.pdf`가 있으면 그 숫자와 추출 행 수·마지막 번호를 비교한다.
- 각 파일의 문항번호가 1부터 마지막 번호까지 연속인지 확인한다.
- CSV가 UTF-8 BOM인지, 열 순서가 정확한지, 요구내용이 비어 있지 않은지 확인한다.
- `수신:`, `담당 보좌관:`, `끝.` 및 담당자 연락처가 CSV에 없는지 확인한다.
- 세부항목·비고가 있는 문항 3개를 실제 PDF 추출 줄과 CSV 결과로 나란히 대조한다.
- 불일치가 있으면 원인을 고친 뒤 다시 검증한다. 실패를 임의로 일치 처리하지 않는다.

완료 후 `PROGRESS.md`에 만든 파일, 기준 CSV와의 일치 여부, 파일별 문항 수, 남은 일과 막힌 점을 기록한다.
