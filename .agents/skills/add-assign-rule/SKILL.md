# 배분규칙 보강

## 언제 쓰는지

- `web/engine.js`의 1순위 정확도가 목표에 미달해 배분기준표를 보강할 때 사용한다.
- 시험 오답을 원인별로 묶고, 사용자가 선택한 수정안만 규칙 사본에 반영해야 할 때 사용한다.
- 원본 배분기준표를 보존하면서 시험 40건과 접수대장 520건의 전후 결과를 비교할 때 사용한다.
- 현재 검증 사례는 시험 40건 1순위 28건, 접수대장 520건 1순위 441건에서 시작해 승인된 세 규칙만 조정한 경우다.

## 순서

1. `AGENTS.md`, `CONTEXT.md`, `PROGRESS.md`, 조직도, 원본 배분기준표, 시험 40건, 접수대장 520건을 읽고 현재 정확도를 계산한다.
2. 오답을 일반 키워드 충돌, 제외어 부족, 키워드 누락, 우선순위 부족 등 원인별로 묶고 원인마다 수정안 하나를 제안한다.
3. 사용자에게 적용할 수정안을 확인받고, 선택되지 않은 규칙은 변경하지 않는다.
4. 원본을 복사한 `rules_보강.csv`에 승인된 변경만 반영하고 모든 과가 조직도 26개 과에 포함되는지 확인한다. 현재 승인 사례는 R136 `민원 서비스` 1→3, R181 `지방채` 1→2, R211 `안전등급` 1→3이다.
5. 원본과 보강본으로 시험 40건·접수대장 520건을 각각 실행해 1순위 정확도, 새 정답, 새 오답을 비교하고 `PROGRESS.md`에 규칙과 결과를 기록한다.

## 끝나는 조건

- 원본 배분기준표가 변경되지 않고 `rules_보강.csv`에 승인된 셀만 달라야 한다.
- 보강 규칙의 과가 모두 조직도 26개 과 안에 있어야 한다.
- 시험 40건과 접수대장 520건의 변경 전·후 1순위 정확도가 확인돼야 한다.
- 시험 40건의 1순위 정답이 30건 이상이고, 변경 전에 맞았으나 변경 후 틀린 새 오답이 0건이어야 한다.
- 실패 사례와 남은 오답을 숨기지 않고 완료 보고와 `PROGRESS.md`에 남겨야 한다.
- 현재 사례의 확인값은 시험 40건 28→31건, 접수대장 520건 441→441건, 두 자료의 새 오답 0건이다.

## 하지 말 것

- 원본 CSV를 덮어쓰거나 과거 접수대장의 값을 바꾸지 않는다.
- 사용자가 고르지 않은 제외어·키워드·우선순위를 임의로 반영하지 않는다.
- 배분규칙이나 부서 목록을 엔진 코드에 복사해 고정하지 않는다.
- 조직도에 없는 과를 새 규칙의 대상으로 만들지 않는다.
- 정확도 목표를 맞추기 위해 시험 정답을 규칙에 직접 하드코딩하거나 새 오답을 누락하지 않는다.
