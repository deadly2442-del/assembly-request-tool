# 자료요구서 문항 분해

`원문/*.pdf`를 읽어 작업 폴더 맨 위에 `split.py`를 만들고, 실행 결과로 `data/문항목록.csv`를 생성한다.

## 준비

1. `AGENTS.md`, `PROGRESS.md`, `CONTEXT.md`와 `처리지침.md` 제2장을 먼저 읽는다.
2. `data/문항목록.csv`가 이미 있으면 현재 출력 계약이자 정답 예시로 읽는다. 기존 `split.py`도 구현 참고자료로 읽는다.
3. `pypdf` 설치 여부를 먼저 확인한다. 없으면 `pip install pypdf`를 사용자에게 보여 주고, 허락을 받은 뒤에만 설치한다.
4. PDF 처리는 `pypdf`만 사용하며, 원문 PDF는 수정하지 않는다. `99_완성본_잠금`은 열거나 풀지 않는다.

## 처리 절차

1. 첫 줄 `○○위원회 ○○ 의원실 자료요구서`에서 위원회와 의원을 추출한다.
2. `수신:` 줄의 제출기한을 `YYYY-MM-DD`로 변환한다.
3. `수신:`, `담당 보좌관:`, `끝.` 줄은 문항에 넣지 않는다. 이름과 연락처를 저장하거나 검증 보고에 표시하지 않는다.
4. 줄 맨 앞의 `숫자.`를 새 문항으로 본다.
5. `가.`, `나.` 등 한글 글머리는 앞 문항의 세부항목으로 넣고, 한 셀에서 ` / `로 연결한다.
6. `※` 줄은 앞 문항의 비고로 넣되 CSV에는 `※`와 뒤따르는 공백을 제거한 본문만 저장한다.
7. 그 밖의 줄은 바로 앞에서 처리한 요구내용·세부항목·비고에 이어 붙인다.
8. 문항 내용이나 문항 수를 코드에 직접 넣지 않고 실행할 때 PDF에서 읽는다.

## 출력

- 코드는 작업 폴더 맨 위의 `split.py` 하나로 만든다.
- 결과 파일은 `data/문항목록.csv`이며 인코딩은 `utf-8-sig`로 한다.
- 열 순서는 `파일명 | 위원회 | 의원 | 제출기한 | 문항번호 | 요구내용 | 세부항목 | 비고`로 고정한다.
- 기존 `data/` 파일과 원문 PDF는 수정하지 않는다. 사용자가 교체한 `data/문항목록.csv`는 검증 중 덮어쓰지 않는다.

## 교체된 문항목록에 맞추기

사용자가 문항목록을 교체했다고 밝히면 교체본을 정답 기준으로 취급한다.

1. PDF를 메모리에서 분석해 `split.py`의 예상 행을 만든다.
2. 기준 CSV와 열 순서, 행 순서, 모든 셀을 비교한다.
3. 차이를 필드별로 묶어 원인을 찾고 일반 추출 규칙을 고친다. 특정 파일명이나 문항 값을 코드에 하드코딩하지 않는다.
4. 예상 결과가 기준 CSV와 완전히 같아진 뒤에만 완료한다.
5. 사용자가 재생성을 요청하지 않았다면 기준 CSV는 그대로 보존한다.

## 확인 기준

파일별로 다음 표를 작성한다.

`파일명 | 파일명의 문항 수 | 뽑은 문항 수 | 마지막 번호 | 번호 연속 | 일치(O/X)`

- 파일명에 `_숫자문항.pdf`가 있으면 그 숫자와 추출 문항 수·마지막 번호를 비교한다.
- 문항번호가 1부터 마지막 번호까지 연속인지 확인한다.
- CSV가 UTF-8 BOM인지, 열 순서가 정확한지, 요구내용이 비어 있지 않은지 확인한다.
- `수신:`, `담당 보좌관:`, `끝.` 및 담당자 이름·연락처가 CSV에 없는지 확인한다.
- 세부항목과 비고가 있는 문항 3개를 실제 PDF 추출 줄과 CSV 결과로 나란히 보여 준다.
- 교체된 기준 CSV가 있으면 행·열·모든 셀과 최종 CSV 바이트까지 비교한다.
- 하나라도 `X`이면 원인을 찾아 일반 규칙을 고친 뒤 다시 실행한다. 실패를 숨기거나 임의로 일치 처리하지 않는다.

완료 후 `PROGRESS.md`에 만든 파일, 핵심 변경, 검증 결과, 남은 일과 막힌 점을 기록한다.
